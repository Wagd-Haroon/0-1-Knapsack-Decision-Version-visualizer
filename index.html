NP-CompleteDecision Problem
📌 What is it?

Given n items with weights and values, a capacity W and target value V: does any subset exist with total weight ≤ W AND total value ≥ V? This YES/NO question is the decision version.

🌍 Real-world uses

Cargo loading, portfolio selection, memory cache management, cutting stock, drug dose optimization — any problem of selecting a subset of items under a capacity constraint.

⚡ Why is it hard?

NP-complete — no known polynomial-time algorithm. For n=50 items, brute force checks 2⁵⁰ ≈ 10¹⁵ subsets. DP is pseudo-polynomial O(nW), fast when W is small but exponential in input bit-length.

0/1 Knapsack — Algorithm Overview
💡 Core Idea

Break the problem into overlapping subproblems. Build a 2-D table where each cell dp[i][w] stores the maximum value achievable using the first i items within capacity w. Each subproblem is solved once and reused.

⚙️ How It Works
1
Create a table of size (n+1) × (W+1). Set all cells in row 0 to 0 (base case: 0 items → 0 value).
2
For each item i (row 1..n) and each capacity w (0..W), compute two choices:
3
Exclude item i: best value without it → dp[i−1][w]
4
Include item i (if wi ≤ w): add vi to best value for remaining cap → dp[i−1][w−wᵢ] + vᵢ
5
Store the maximum of both: dp[i][w] = max(exclude, include)
6
Answer: dp[n][W] = optimal value. Decision = YES if dp[n][W] ≥ V.
7
Traceback: walk the table backwards to recover which items were selected.
⏱️ Complexity
Time
O(nW)
Space
O(nW) / O(W) rolling
✓ Exact — always optimal Pseudo-polynomial
O(nW) is pseudo-polynomial: W is a numeric value, not the number of input bits. If W needs b bits, O(nW) = O(n·2b) — exponential in b.
✅ When to Use
When you need the guaranteed optimal answer and W is not extremely large.
Practical for most real-world W (logistics, budgeting, caching).
Not suitable when W is astronomically large (e.g. W = 21000) — table becomes infeasible.
💡 Core Idea

Exhaustive search over every possible subset of items. Since each item is either taken (1) or not taken (0), there are exactly 2n subsets. Every subset is checked against the weight and value constraints.

⚙️ How It Works
1
Represent each subset as a bitmask from 0 to 2n−1. Bit i = 1 means item i is included.
2
For each bitmask, sum the weights of selected items. If total weight > W, the subset is infeasible — skip it.
3
For feasible subsets, sum the values. Track the best (highest-value) feasible subset.
4
If any feasible subset has total value ≥ V, the decision is YES. Otherwise NO.
5
After checking all 2n subsets, the best feasible subset is guaranteed to be globally optimal.
⏱️ Complexity
Time
O(n·2ⁿ)
Space
O(n) bitmask
✓ Exact — guaranteed optimal Exponential time
✅ When to Use
For very small inputs (n ≤ 16) where the exponential cost is acceptable.
For exhaustive verification, testing, or educational purposes.
Not suitable for n > 20. At n = 30, checking 230 ≈ 1 billion subsets is already too slow for most applications.
💡 Core Idea

Sort items by value-to-weight ratio (v/w) in descending order. Greedily select items from the top of this sorted list, taking each item if it fits within remaining capacity. Never backtracks or reconsiders earlier choices.

⚙️ How It Works
1
Compute the ratio vi/wi for every item.
2
Sort all items by ratio descending — highest "bang per unit weight" first. O(n log n).
3
Iterate through the sorted list. For each item, if it fits (current weight + wi ≤ W), take it.
4
If it doesn't fit, skip it entirely (0/1: no fractions allowed).
5
Report the total value collected. Decision = YES if total value ≥ V.
⏱️ Complexity
Time
O(n log n)
Space
O(n) sorted list
⚠ Heuristic — may not be optimal
Important: Greedy is optimal for fractional knapsack (items can be split). For 0/1 knapsack, it is only a heuristic — a high-ratio item can fill capacity that would be better used by a combination of other items.
✅ When to Use
When a fast approximation is acceptable and n is large.
For fractional knapsack, where greedy is provably optimal.
Not suitable when the exact optimal answer is required for 0/1 Knapsack — use DP instead.

Formal Definition

Given n items with weights w₁..wₙ and values v₁..vₙ, a capacity W and target value V:
does there exist S ⊆ {1..n} with Σwᵢ ≤ W and Σvᵢ ≥ V?

Decision vs Optimization Version

Optimization: "What is the maximum total value achievable with weight ≤ W?" — returns a number (NP-hard).

Decision: "Does any subset achieve total weight ≤ W AND total value ≥ V?" — returns YES or NO (NP-complete).

How DP answers both: DP computes dp[n][W] = maximum achievable value. The decision answer is simply whether dp[n][W] ≥ V. The optimization and decision versions are computationally equivalent — each can be solved using the other.

✈️ Cargo Loading

Select cargo items within a weight limit to maximize total revenue. Classic 0/1 Knapsack — each item is either loaded or not.

💰 Portfolio Selection

Choose investments within a budget (W) to maximize expected return (V). Each investment is a binary decision.

💊 Drug Dosing

Select drug combinations within a maximum dose, maximizing therapeutic effect. Safety constraints = weight limit.

📱 Memory Cache

Which data to keep in cache (W bytes) to maximize hit rate (V). Binary — data is in cache or not.

📐 Design Paradigm: Dynamic Programming (Bottom-Up)

DP solves Knapsack by breaking it into overlapping subproblems. The key insight: if we know the best answer for items 1..i−1, we can extend it to item i by choosing to include or exclude it. Each subproblem is solved once and stored — never recomputed.

🗂 State Definition

dp[i][w] = maximum value achievable using items 1..i with capacity at most w.

The table has (n+1) rows (one per item, plus a base row) and (W+1) columns (one per capacity 0..W). We fill it row by row, left to right.

🏁 Base Cases

dp[0][w] = 0  for all w  → no items available, best value = 0

dp[i][0] = 0  for all i  → zero capacity, nothing can be packed

These two base cases anchor the entire table — every other cell is built from them upward.

🔁 Recurrence — The Include / Exclude Decision
if wᵢ > w: dp[i][w] = dp[i-1][w] ← item too heavy, must exclude else: dp[i][w] = max( dp[i-1][w], ← EXCLUDE: best without item i dp[i-1][w-wᵢ] + vᵢ ← INCLUDE: use item i, add its value )
❌ Exclude Item i
value = dp[i-1][w]
Skip item i. The best value is whatever we could achieve using items 1..i−1 at the same capacity w. Item i contributes nothing.
✅ Include Item i
value = dp[i-1][w-wᵢ] + vᵢ
Take item i. Reserve wᵢ units of capacity for it. Use the remaining w−wᵢ capacity optimally with items 1..i−1, then add vᵢ.
Key insight: At each state (i, w), we choose whichever option gives the higher value. This works because the problem has optimal substructure — the best answer for (i, w) is built from the best answers for smaller subproblems — and overlapping subproblems — many cells share the same sub-answers, which we reuse instead of recomputing.
Worked Example — Computing dp[2][5]
Items: Item 1 (w=2, v=3), Item 2 (w=3, v=4). Capacity w = 5.
Exclude item 2
dp[1][5] = 3
Best value using only item 1 at cap 5
Include item 2
dp[1][2] + 4 = 3 + 4 = 7
Reserve 3 for item 2; use cap 2 for items 1..1
Result dp[2][5]
max(3, 7) = 7
Include wins — store 7
🔍 Traceback — Recovering the Chosen Items

After the table is filled, dp[n][W] contains the maximum achievable value. To find which items were chosen, walk backwards through the table:

Start at i = n, w = W while i > 0: if dp[i][w] == dp[i-1][w]: item i was NOT included → move to row i-1 else: item i was INCLUDED → record item i w ← w - wᵢ move to row i-1
dp[i][w] = dp[i−1][w]
The value did not change when we added item i. Item i was excluded — move up one row without changing the capacity pointer.
dp[i][w] ≠ dp[i−1][w]
The value improved when we added item i. Item i was included — record it, subtract wᵢ from the capacity pointer, move up one row.
This reconstruction runs in O(n) time — we visit at most n rows. It requires the full (n+1)×(W+1) table. If only the optimal value is needed (not the items), a rolling O(W) array suffices.
⏱️ Time & Space Complexity
How we get O(nW):
①We fill a table of size (n+1) × (W+1) — that is n·W cells to compute (ignoring the base row).
②Each cell requires exactly one comparison (exclude vs include) — O(1) per cell.
③Total: O(n · W) operations. Traceback adds O(n) — negligible.

• ∴ DP does not place Knapsack in P
🔑 Key Properties of the DP Solution
Optimal Substructure
The optimal solution to a problem of size (i, w) is built from optimal solutions to smaller subproblems (i−1, w) and (i−1, w−wᵢ). This is why DP applies here.
Overlapping Subproblems
Many cells (i, w) share the same sub-answers — e.g., dp[i−1][w] is referenced by every cell in row i. DP solves each subproblem once and stores it, avoiding exponential recomputation.
Deterministic Table Fill
The table is filled in a fixed order: row 0 first (base cases), then rows 1..n left to right. Each cell depends only on the row above — no cycles, no ambiguity.
📐 Why dp[n][W] is the Globally Optimal Value — Inductive Proof
Base Case
dp[0][w] = 0 for all w. Correct — with zero items available, the maximum achievable value is zero regardless of capacity.
Inductive Step
Assume dp[i−1][w] is optimal for all w. Then dp[i][w] = max(dp[i−1][w], dp[i−1][w−wᵢ] + vᵢ) is optimal — because every subset of items 1..i either excludes item i (best is dp[i−1][w]) or includes item i (best is dp[i−1][w−wᵢ] + vᵢ). These two cases are exhaustive and mutually exclusive. Taking the maximum covers all possibilities. Therefore dp[i][w] is optimal.
Conclusion ∎
By induction over i = 1..n, dp[n][W] holds the globally optimal value using all n items with capacity W. The decision answer dp[n][W] ≥ V is therefore always correct. ∎
⚠️ Why Greedy Fails for 0/1 Knapsack

Greedy by value/weight ratio is optimal for fractional knapsack (items can be split) but not for 0/1 knapsack — items are whole or nothing.

Classic counterexample: A(w=10,v=60), B(w=20,v=100), C(w=30,v=120). W=50.
Ratios: A=6.0, B=5.0, C=4.0.
Greedy picks A+B → value 160. Optimal is B+C → value 220.

Fractional vs 0/1 Knapsack

Fractional: Items can be split. Greedy by v/w is provably optimal via an exchange argument — any deviation from the greedy order can only decrease total value.

0/1: Items are indivisible. The exchange argument breaks down. A high-ratio item can block a better combination. DP considers all combinations implicitly.

Class P

Problems solvable in polynomial time O(nᵏ). Sorting, shortest path, primality test. These are "efficiently solvable."

Class NP

Problems where a YES-answer can be verified in polynomial time. "NP" = Non-deterministic Polynomial, not "Not Polynomial." P ⊆ NP always.

NP-Complete

In NP AND NP-hard — every NP problem reduces to it in polynomial time. Solving any NP-complete in poly-time solves all NP. 0/1 Knapsack (decision) is NP-complete.

Certificate & Verifier

For Knapsack: certificate = subset S of item indices. Verifier checks Σwᵢ ≤ W and Σvᵢ ≥ V in O(n). Since verification is polynomial, Knapsack ∈ NP.

Polynomial-Time Reduction

A ≤ₚ B: transform any instance of A into B in polynomial time, preserving YES↔YES. Used to prove NP-hardness: Subset Sum ≤ₚ Knapsack.

Pseudo-Polynomial Time

O(nW) is polynomial in W's numeric value but exponential in its bit-length (log₂W bits). O(nW) = O(n·2^(log W)) — exponential in input size. Does NOT place Knapsack in P.

Foundation: Complexity Classes
Before proving anything, we need to agree on what these terms mean. Each box below defines a key concept used throughout the proof.
Class P
Problems that can be solved in polynomial time — O(nk) for some constant k. These are considered "efficiently solvable." Examples: sorting, shortest path, primality testing.
Class NP
Problems where a proposed YES answer can be verified in polynomial time. "NP" stands for Non-deterministic Polynomial — it does not mean "Not Polynomial." Every problem in P is also in NP.
NP-Hard
A problem X is NP-hard if every problem in NP can be reduced to X in polynomial time. NP-hard problems are at least as hard as anything in NP. They may or may not themselves be in NP.
NP-Complete
A problem that is both in NP and NP-hard. These are the hardest problems within NP. If any single NP-complete problem has a polynomial-time solution, then all NP problems do (P = NP).
🏷️
Certificate
A short, proposed solution to a YES instance. For Knapsack, the certificate is the list of chosen item indices. The certificate must be polynomial in size.
🔎
Verifier
An algorithm that takes an input and a certificate, then checks in polynomial time whether the certificate proves YES. The verifier does not need to find the answer — only confirm it.
🔄
Poly-Time Reduction
A ≤p B means: any instance of A can be converted into an instance of B in polynomial time, preserving YES↔YES. If B is easy, so is A.
📐
Proof Strategy
To prove X is NP-complete: (1) show X ∈ NP using a certificate and polynomial verifier, and (2) show X is NP-hard by reducing a known NP-complete problem to X.
Complexity Class Relationships
PEvery problem in P is also in NP. Solvable efficiently ⟹ verifiable efficiently.
NPContains all problems whose YES answers can be verified in polynomial time, including all of P.
NP-CompleteThe intersection of NP and NP-Hard — the hardest problems inside NP. Every NP problem reduces to each of them.
NP-HardAt least as hard as all NP problems. Some NP-hard problems are not even in NP (no efficient verifier exists for them).
To prove a problem is NP-complete: (1) show it is in NP using a certificate and polynomial verifier, and (2) show it is NP-hard by polynomial reduction from a known NP-complete problem.

Knapsack ∈ NP — Certificate and Verifier

A problem is in NP if there exists a polynomial-time verifier: an algorithm that, given the input and a short certificate, can confirm in polynomial time whether the answer is YES. We provide both the certificate and the verifier for Knapsack.

Certificate
The certificate for a YES instance is simply the list of chosen item indices. For our example: S = {1, 2}. This list has at most n entries, so its size is O(n) — polynomial.
Verifier
Given input (items, W, V) and certificate S, the verifier performs two checks, each requiring at most n additions:
Check 1: Σi∈S wi ≤ W ? Check 2: Σi∈S vi ≥ V ? Total: O(n)

Certificate: S = {1, 2} (at most n indices, so O(n) size) Check 1: w1 + w2 = 3 + 5 = 8 ≤ W = 8 ✓ (n additions) Check 2: v1 + v2 = 3 + 5 = 8 ≥ V = 8 ✓ (n additions) Verification time: O(n) — polynomial ✓

Both checks run in O(n) time. The certificate has polynomial size. Therefore a polynomial-time verifier exists for Knapsack.

Conclusion: Knapsack ∈ NP. ∎

Key distinction: Showing Knapsack ∈ NP does not mean it is easy to find the right subset. It only means that if someone hands you a candidate subset, you can quickly verify whether it is valid. The difficulty of finding the subset is the separate NP-hardness question addressed in Step 2.

Reduction from Subset Sum — Establishing NP-Hardness

To prove NP-hardness, we show that every NP-complete problem reduces to Knapsack in polynomial time. We use Subset Sum — a well-known NP-complete problem — as our starting point. If we could solve Knapsack efficiently, we could solve Subset Sum too, which would collapse the entire NP class.

Subset Sum — Known NP-Complete Problem
Input: A multiset of positive integers A = {a1, a2, …, an} and a target integer t.
Question: Is there a subset A' ⊆ A whose elements sum to exactly t?
Example: A = {3, 5, 9}, t = 8 Answer: YES — subset {3, 5} sums to 3 + 5 = 8
The Construction

Given any Subset Sum instance ⟨A, t⟩, we build a 0/1 Knapsack instance as follows:

For each element ai ∈ A: create Knapsack item i with weight wi = ai and value vi = ai Set knapsack capacity W = t Set target value V = t
Subset Sum Instance
A = {3, 5, 9}
target t = 8
⟶
transform O(n)
Knapsack Instance
Item 1: w=3, v=3
Item 2: w=5, v=5
Item 3: w=9, v=9
W = 8, V = 8
Why Does Setting Weight = Value Work?

This is the key insight of the reduction. Because every item has weight equal to value (both equal to ai), any selected subset produces the same total weight and total value. We can therefore use the two Knapsack constraints to force an exact sum:

selected items = S total weight = Σi∈S wi = Σi∈S ai total value = Σi∈S vi = Σi∈S ai ⟹ weight = value = (selected sum)
Knapsack requires:
selected sum ≤ t (weight constraint)
selected sum ≥ t (value constraint)

Both compare the same quantity (the selected sum) to t. The only way to satisfy both is:
selected sum = t exactly

— which is precisely the Subset Sum condition.
Geometric insight: By setting weight = value, the two Knapsack constraints squeeze the selected sum from both sides — it can be neither too large nor too small. This forces it to hit the exact target t, transforming a "range" problem into an "exact" problem.
3

Correctness — Both Directions

A reduction is only valid if the transformation preserves answers in both directions. We must show that the Subset Sum instance is YES if and only if the constructed Knapsack instance is YES.

→ Forward Direction:   Subset Sum YES  ⟹  Knapsack YES
Assume: There exists a subset A' ⊆ A with Σa∈A' a = t (Subset Sum is YES).

Claim: Select the corresponding Knapsack items — those whose index i satisfies ai ∈ A'.

• Total weight = Σwi = Σai = t = W   ✓   satisfies weight ≤ W
• Total value  = Σvi = Σai = t = V   ✓   satisfies value ≥ V

Both Knapsack constraints are met, so the Knapsack instance is YES. ∎
← Backward Direction:   Knapsack YES  ⟹  Subset Sum YES
Assume: There exists a subset S of Knapsack items with total weight ≤ t and total value ≥ t (Knapsack is YES).

Key observation: Since wi = vi = ai for every item, the total weight of S and the total value of S are always equal. Let s = Σi∈S ai.

• From the weight constraint: s ≤ t
• From the value constraint:  s ≥ t

Therefore s = t exactly.

The same subset A' = {ai : i ∈ S} satisfies Σa∈A' a = t, so the Subset Sum instance is YES. ∎
Formal proof (step-by-step)
1. Assume Knapsack is YES: ∃ S ⊆ {1..n} with Σᵢ∈S wᵢ ≤ t and Σᵢ∈S vᵢ ≥ t 2. By construction wᵢ = vᵢ = aᵢ for every i. Let s = Σᵢ∈S aᵢ. Then: total weight = s and total value = s (same quantity) 3. Weight constraint gives: s ≤ t Value constraint gives: s ≥ t 4. Therefore: s = t (squeezed from both sides) 5. Set A' = { aᵢ : i ∈ S }. Then Σ(a∈A') a = s = t ✓ 6. ∴ The Subset Sum instance is YES. ∎
Numerical Verification (A = {3, 5, 9}, t = 8):
Forward direction:
Subset Sum: {3, 5} sums to 8 = t ✓ Knapsack S={1,2}: weight=8≤8 ✓ value =8≥8 ✓ Knapsack is YES ✓
Backward direction:
Knapsack S={1,2}: weight=8, value=8 8 ≤ 8 AND 8 ≥ 8 → 8 = 8 = t ✓ Subset Sum: {a₁,a₂}={3,5} 3+5=8=t → Subset Sum is YES ✓

The Construction Runs in Polynomial Time

A reduction A ≤p B is only valid if the transformation from A to B runs in polynomial time. We verify this for our construction:

O(n) is therefore a genuine polynomial bound in the input size. ∎

The transformation maps YES-instances to YES-instances and NO-instances to NO-instances (proven in Step 3). The construction itself is polynomial. Therefore Subset Sum ≤p Knapsack. ∎

Why Dynamic Programming Does Not Contradict NP-Completeness

Students often ask: "DP solves Knapsack in O(nW) — isn't that polynomial time?" The answer is no. O(nW) is pseudo-polynomial, not polynomial in the formal sense. Here is why.

The Problem With O(nW)
Polynomial time means polynomial in the number of input bits, not in numeric values. The number W requires only b = ⌈log2(W+1)⌉ bits to represent in binary. As b grows by 1, W doubles — but the DP table doubles in size too:
W = 1,000,000 → b ≈ 20 bits DP table: n × 1,000,000 cells W = 2^1000 → b = 1001 bits DP table: n × 2^1000 cells ← impossible!
O(nW) = O(n · 2b)
This is exponential in the bit-length b of W. Polynomial time requires the exponent to be bounded by a constant.
Pseudo-Polynomial Defined
An algorithm is pseudo-polynomial if its time complexity is polynomial in the numeric values of the input, but exponential in the number of bits used to encode those values. DP for Knapsack is pseudo-polynomial: it runs in O(nW) where W is a value, not a bit-count. This does not place the problem in P.
Practical note: DP is excellent and widely used when W is small or moderate — as in real-world logistics, budgeting, and resource allocation. NP-completeness describes worst-case hardness over all possible inputs, including adversarially large W. The existence of a pseudo-polynomial algorithm does not prove the problem is in P or contradict its NP-completeness.

🧭 Which algorithm should you use?
Choose based on your input size and whether you need an exact answer or a fast approximation.
⚡ Brute Force
Exact but exponential
Use only for very small n (typically n ≤ 16) or for exhaustive verification. It guarantees the correct answer by checking every subset, but becomes completely impractical as n grows. At n = 30, you would need to check over 1 billion subsets.
📊 Dynamic Programming
Exact & practical when W is manageable
Use when you need the optimal answer and the knapsack capacity W is not extremely large. It is dramatically faster than Brute Force for real-world inputs. Remember that its performance depends on W — the larger W is, the more memory and time it needs.
🎯 Greedy Heuristic
Fast but not guaranteed
Use when speed matters more than exactness and an approximate answer is acceptable. It is always the fastest option but may miss the optimal solution for 0/1 Knapsack because items cannot be split. It is, however, optimal for the fractional knapsack variant.
